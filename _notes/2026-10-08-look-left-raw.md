## Transcript, Rob speaking (approx 10:00 to 15:00)

I got excited about how I have many Claude chats going, but actually not that many, because I've given them very broad purposes. One's monitoring my communications at work. One is, this is a useful fiction, I've got one called Main that does most of my work, and is the thing I'm working in right now, and it also has in its head my to-dos that I'm really worried about getting done, and we're working through them because I'm single-threaded. When we can task stuff off to work in parallel, we do, but it's from that main thread. So there's a single point of contact.

Before I came here I was an obsessive user of terminals and Emacs, and now I haven't used them in weeks, to the point where when I just opened Emacs to show [a new colleague] something, I had to struggle for a second to remember a really basic keyboard shortcut. It's starting to fall away. The reason is I'm using Claude Desktop for everything, and I realised I could expand the scope of that. It can already do everything on my computer, not limited to talking to SM-10. Mediated by me saying yes, I do want you to run that command, but still, it's doing it. I'm not leaving the UI.

Yesterday we set up something we're loosely calling a company brain, files on SharePoint. Along the way: bits of our estate are naturally going to want to be exposed to LLMs anyway, so read-only access to email is desirable. As of this morning I have Claude Code with a Python watcher on my email that will wake it up if a new email appears. It checks on a 90-second cadence. Which means if I want to check my emails, I just have to look left rather than switch window. It's doing the same for Slack, and for updates to SharePoint files. (How can you look left?) The Claude desktop literally has a list of chats, and they show a circle next to them when something new happens. (Are you on Claude Code in the desktop?) Yes. Exclusively.

I also found out it's now happy to run ChatGPT, so that's another web app I'm trying to avoid using now, but still using, if you get what I mean.

Lastly, I'm deliberately careering towards wanting a single interface for my entire operating system. I have a thought that someone soon is going to have an operating system designed around an LLM driver for you. I was saying to a friend yesterday, I resent unlocking my phone. I don't think it adds any value having to unlock it and all this stuff. I just want to start a conversation. Maybe text out, voice out optionally. I don't want to navigate with my thumbs to where I need to be, because I don't need to any more.

Room: "there's surely going to be a thing where there's no start button, there's no apps, there's just talk, submit." "Back to DOS." "The idea of an operating system GUI is stapled to a particular level of abstraction, like binary, then assembly, then eventually JavaScript or C#." "If you're a CISO you're not using the computer to do stuff, you're telling people to use the computer." "Your user-facing layer becomes a thin edge on a fleet of ephemeral containers." "Running a team from your phone."
